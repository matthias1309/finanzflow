# REQ-014 — Mobile-Responsive UI

**Status:** approved
**Created:** 2026-05-02
**Traced by:** _(pending ARCH and TEST)_

## User Story

As a user,
I want to use FinanzFlow fully on my smartphone (iOS Safari, Android Chrome),
so that I can check and manage my finances on the go, not just at a desktop.

## Background

All pages adapt to screen widths from 320 px. Below 768 px, the desktop sidebar is replaced by a
hamburger menu with a slide-in drawer.

## Acceptance Criteria

### AC-014-01: Hamburger menu replaces the sidebar on mobile

```gherkin
Given the user opens the app on a smartphone (<768 px)
Then a fixed top bar with logo and hamburger icon is shown
And the sidebar is not visible
```

### AC-014-02: Tapping the hamburger icon opens the drawer

```gherkin
Given the user is on a smartphone (<768 px)
When the user taps the hamburger icon
Then the sidebar slides in as a drawer from the left
And a dark backdrop covers the content behind it
```

### AC-014-03: Tapping a nav link closes the drawer and navigates

```gherkin
Given the user is on a smartphone (<768 px) with the drawer open
When the user taps a nav link in the drawer
Then the drawer closes
And the requested page is shown
```

### AC-014-04: Tapping the backdrop closes the drawer without navigating

```gherkin
Given the user is on a smartphone (<768 px) with the drawer open
When the user taps the backdrop
Then the drawer closes without navigating
```

### AC-014-05: Dashboard KPI cards adapt their column count to screen width

```gherkin
Given the user is on the Dashboard
When the screen width is < 640 px
Then the KPI cards are shown in 2 columns
When the screen width is >= 1024 px
Then the KPI cards are shown in 4 columns
```

### AC-014-06: Dashboard account cards adapt their column count to screen width

```gherkin
Given the user is on the Dashboard
And accounts exist
When the screen width is < 640 px
Then the account overview is shown in 1 column
When the screen width is >= 640 px and < 1024 px
Then the account overview is shown in 2 columns
```

### AC-014-07: Transactions page header stacks on narrow screens

```gherkin
Given the user is on the Transactions page
When the screen width is < 768 px
Then the title and filter controls stack vertically (flex-col)
```

### AC-014-08: Transaction table scrolls horizontally instead of clipping

```gherkin
Given the user is on the Transactions page
When the transaction table is wider than the viewport
Then it is horizontally scrollable (no content is clipped)
```

### AC-014-09: All pages keep a minimum padding and avoid overlap on narrow screens

```gherkin
Given the screen width is < 768 px
Then the horizontal padding of all page headers and content is at least 16 px (p-4)
And no content element is clipped or overlaps the top bar
```

## Notes

- Hamburger menu: `Menu` icon (lucide-react), drawer via `transition-transform` (no external
  package).
- Sidebar: `fixed inset-y-0 left-0` on mobile, `md:static` on desktop.
- Breakpoints: Tailwind defaults (`sm` = 640 px, `md` = 768 px, `lg` = 1024 px).
- TDD exception: purely visual changes with no measurable assertions — no automated test layer for
  this REQ (see `.claude/rules/v-model.md`, "TDD Rule").
