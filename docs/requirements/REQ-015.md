# REQ-015 — Multi-User Management

**Status:** approved
**Created:** 2026-05-03
**Traced by:** ARCH-015, TEST-015

## User Story

As an admin of FinanzFlow,
I want to create and manage additional user accounts,
in order to let several people use the app with the same data access rights.

## Background

FinanzFlow supports multiple user accounts. All users share the same dataset (accounts,
transactions, categories). There are two roles:

- **Admin**: Can manage all data and create, edit, and delete users, as well as set other users'
  passwords. Can grant or revoke admin rights for other users.
- **Regular user**: Can manage all data, but has no user management access. Can only change their
  own password (via a profile dropdown in the navigation).

**Data model:** Users are stored in the `users` table (`id`, `username`, `passwordHash`,
`isAdmin`, `totpSecret`, `totpEnabled`, `createdAt`).

**Seeding at startup:** On server start, the user from `APP_USER` and `APP_PASSWORD_HASH` is
synced into the DB (upsert with `isAdmin=true`). If these environment variables are missing in
production mode, the start fails (see REQ-001).

**Protection of the last admin:** At least one admin user must always exist. The last admin can
neither be deleted nor downgraded to a regular user.

**TOTP:** Each user sets up their own TOTP. New users are guided through the TOTP setup flow on
first login (see REQ-013). Admins can reset any user's TOTP.

**Session invalidation:** If an admin changes another user's password or resets their TOTP, all
active sessions of that user are invalidated.

**UI:** The user management page (`/users`) is accessible only to admin users. Regular users
change their password via a profile dropdown in the navigation.

## Acceptance Criteria

### AC-015-01: Admin sees the user list

```gherkin
Given the app runs in production mode
And an admin user "admin" is logged in
And at least one other user "lisa" exists
When the admin opens the page "/users"
Then a list of all users is shown
And username, admin status, and TOTP status are visible for each user
```

### AC-015-02: Admin creates a new user

```gherkin
Given the app runs in production mode
And an admin user "admin" is logged in
When the admin clicks "Benutzer anlegen"
And enters username "lisa" and an initial password
And submits the form
Then "lisa" appears in the user list
And "lisa" has no admin rights
And TOTP is not yet set up for "lisa"
```

### AC-015-03: Username is already taken

```gherkin
Given the app runs in production mode
And an admin user "admin" is logged in
And a user "lisa" already exists
When the admin tries to create another user named "lisa"
Then the form stays open
And an error message "Benutzername bereits vergeben" is shown
```

### AC-015-04: Admin grants admin rights

```gherkin
Given the app runs in production mode
And an admin user "admin" is logged in
And a user "lisa" without admin rights exists
When the admin enables the admin status for "lisa"
Then "lisa" has admin rights
And can open the page "/users"
```

### AC-015-05: Admin revokes admin rights

```gherkin
Given the app runs in production mode
And an admin user "admin" is logged in
And a user "lisa" with admin rights exists
And at least one other admin exists
When the admin disables the admin status for "lisa"
Then "lisa" no longer has admin rights
```

### AC-015-06: Last admin cannot be downgraded

```gherkin
Given the app runs in production mode
And an admin user "admin" is logged in
And "admin" is the only admin
When the admin tries to revoke their own admin status
Then the admin status remains unchanged
And an error message "Letzter Admin kann nicht degradiert werden" is shown
```

### AC-015-07: Admin deletes a user

```gherkin
Given the app runs in production mode
And an admin user "admin" is logged in
And a user "lisa" exists
When the admin clicks "Löschen" for "lisa"
And confirms the action in the confirmation dialog
Then "lisa" is no longer in the user list
And all active sessions of "lisa" are invalidated
```

### AC-015-08: Last admin cannot be deleted

```gherkin
Given the app runs in production mode
And an admin user "admin" is logged in
And "admin" is the only admin
When the admin tries to delete themselves
Then an error message "Letzter Admin kann nicht gelöscht werden" is shown
And the user is preserved
```

### AC-015-09: Admin sets another user's password

```gherkin
Given the app runs in production mode
And an admin user "admin" is logged in
And a user "lisa" exists
When the admin sets a new password for "lisa"
Then "lisa" can log in with the new password
And all active sessions of "lisa" are invalidated
```

### AC-015-10: User changes their own password successfully

```gherkin
Given "lisa" is logged in
When "lisa" enters the old and new password in the profile dropdown and confirms
Then the new password is active
And the current session is preserved
```

### AC-015-11: User changes their own password — wrong old password

```gherkin
Given "lisa" is logged in
When "lisa" enters a wrong old password
Then the form stays open
And an error message "Aktuelles Passwort falsch" is shown
```

### AC-015-12: Regular user has no access to /users

```gherkin
Given "lisa" is logged in and has no admin rights
When "lisa" opens the page "/users"
Then "lisa" is redirected to the Dashboard
And an error message "Kein Zugriff" is shown
```

### AC-015-13: Admin resets a user's TOTP

```gherkin
Given the app runs in production mode
And an admin user "admin" is logged in
And a user "lisa" has TOTP set up
When the admin clicks "2FA zurücksetzen" for "lisa"
And confirms the action in the confirmation dialog
Then TOTP is disabled for "lisa"
And all of "lisa"'s recovery codes are invalid
And "lisa" is guided through the TOTP setup flow on the next login
And all active sessions of "lisa" are invalidated
```

### AC-015-14: Env sync at startup — user does not exist yet

```gherkin
Given APP_USER is set to "admin"
And APP_PASSWORD_HASH is set to a valid bcrypt hash of "secret"
And no user named "admin" exists in the DB
When the server starts
Then a user "admin" with isAdmin=true is created in the DB
And the password hash matches APP_PASSWORD_HASH
```

### AC-015-15: Env sync at startup — user is updated

```gherkin
Given APP_USER is set to "admin"
And APP_PASSWORD_HASH is set to a new bcrypt hash
And a user "admin" already exists with a different password hash
When the server starts
Then "admin"'s password hash is updated to APP_PASSWORD_HASH
And isAdmin remains true
```

### AC-015-16: New user is guided through TOTP setup on first login

```gherkin
Given "lisa" was newly created and TOTP is not yet set up
When "lisa" logs in successfully with username and password
Then "lisa" is redirected directly to the TOTP setup flow (see REQ-013)
And can only reach the Dashboard after completing TOTP setup
```

## Notes

- API endpoints: `GET /api/users`, `POST /api/users`, `PATCH /api/users/:id`,
  `DELETE /api/users/:id`, `PATCH /api/users/:id/password`, `POST /api/users/:id/2fa-reset`
- Admin middleware protects all `/api/users` endpoints except `PATCH /api/users/:id/password`
  (authentication only required; a user may only use their own ID)
- Session invalidation on password reset and TOTP reset by an admin: all sessions of the affected
  user are removed from the session store. Requires access to the session store in the route.
- Minimum password length: 8 characters, validated via Zod in `shared/schema.ts`.
- User IDs in API requests: integer (DB PK), not username — avoids path issues with special
  characters in usernames.
- Migration of existing TOTP data: during the DB migration, the existing TOTP secret from the
  single-user setup is transferred to the `users` entry of the seed admin.
