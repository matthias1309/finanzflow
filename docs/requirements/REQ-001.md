# REQ-001 — Authentication & Access Control

**Status:** approved
**Created:** 2026-04-23
**Traced by:** ARCH-001, TEST-001

> **Note:** REQ-001 was extended by REQ-013. HTTP Basic Auth was replaced by session-based
> authentication with TOTP (2FA). The login page and the TOTP setup flow are described in
> REQ-013.

## User Story

As a user of FinanzFlow,
I want the app to be protected by a password and a second factor,
in order to keep my personal financial data safe from third parties who know the URL.

## Background

FinanzFlow is deployed on a public URL. All routes — API and frontend — must be protected. The
app uses its own login page with session-based authentication: after a successful login
(password + TOTP), a session cookie is set. HTTP Basic Auth is no longer used.

User data (username, password hash, admin flag, TOTP secret) is stored in the `users` table. On
server start, the user from `APP_USER` and `APP_PASSWORD_HASH` is synced into the DB (upsert with
`isAdmin=true`). Creating and managing further users is described in REQ-015.

In development mode (`NODE_ENV=development`), auth is fully disabled so that development and test
workflows are not blocked.

**Session configuration:**
- Cookie flags: `httpOnly`, `Secure`, `SameSite=Strict`
- Default session duration: 8 hours (overridable via `SESSION_MAX_AGE_HOURS`)
- After expiry: redirect to the login page

## Acceptance Criteria

### AC-001-01: Successful login with correct password and TOTP

```gherkin
Given the app runs in production mode
And a user "admin" with password "secret" exists in the database
And 2FA is already set up for "admin"
And the user is on the login page
When the user enters "admin" and "secret" and submits
Then the TOTP input mask appears
When the user enters a valid 6-digit TOTP code
Then a session cookie is set
And the user is redirected to the Dashboard
```

### AC-001-02: Wrong password is rejected

```gherkin
Given the app runs in production mode
And a user "admin" with password "secret" exists in the database
And the user is on the login page
When the user enters "admin" and a wrong password
Then the user stays on the login page
And an error message "Benutzername oder Passwort falsch" is shown
And no session cookie is set
```

### AC-001-03: Wrong TOTP code is rejected

```gherkin
Given the app runs in production mode
And a user "admin" with password "secret" exists in the database
And 2FA is already set up for "admin"
And the user has entered the password correctly
And the TOTP input mask is visible
When the user enters a wrong 6-digit code
Then the user stays on the TOTP input mask
And an error message "Ungültiger Code" is shown
And no session cookie is set
```

### AC-001-04: Login with a recovery code

```gherkin
Given the app runs in production mode
And a user "admin" with password "secret" exists in the database
And 2FA is already set up for "admin"
And the user has entered the password correctly
And the TOTP input mask is visible
When the user enters a valid recovery code
Then a session cookie is set
And the user is redirected to the Dashboard
And the used recovery code is permanently invalid
```

### AC-001-05: Brute-force protection on login attempts

```gherkin
Given the app runs in production mode
When the same IP sends 10 failed login attempts within 15 minutes
Then the 11th attempt returns status 429
And the error message contains "Zu viele Login-Versuche"
```

### AC-001-06: Session expires

```gherkin
Given the app runs in production mode
And the user is logged in
And the session has expired
When the user requests a protected page
Then the user is redirected to the login page
```

### AC-001-07: Explicit logout

```gherkin
Given the app runs in production mode
And the user is logged in
When the user clicks "Abmelden"
Then the session is destroyed server-side
And the cookie is deleted
And the user is redirected to the login page
```

### AC-001-08: Production start without APP_USER or APP_PASSWORD_HASH fails

```gherkin
Given APP_USER or APP_PASSWORD_HASH is not set
And NODE_ENV is "production"
When the server starts
Then the server exits with a fatal error message
And the error message explains how to generate a password hash
```

### AC-001-09: Development mode allows access without credentials

```gherkin
Given APP_PASSWORD_HASH is not set
And NODE_ENV is "development"
When the user requests a page
Then access is possible without login
```

## Notes

- Password comparison uses `timingSafeEqual` with fixed 256-byte buffers to guard against timing
  attacks. The user record is loaded by username from the `users` table; if it does not exist, a
  dummy comparison is still performed (to prevent a timing leak).
- The brute-force limiter counts only failed requests (`skipSuccessfulRequests: true`).
- Bcrypt cost factor: 10. Password hashes are never logged or returned in API responses.
- TOTP verification: RFC 6238, time window ±1 step (30 s) to tolerate clock drift. Each code can
  only be used once (replay protection).
- Session data is kept server-side in the memory store (memorystore, TTL = session duration). The
  session holds the user ID; all protected routes look up the user by this ID in the DB.
