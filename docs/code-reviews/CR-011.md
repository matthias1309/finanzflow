## Summary

Implements REQ-017 end to end:

- **Parser** (`server/pdfParser.ts`): `ParsedTransaction.counterpartyIban`. N26 and DKB capture
  the IBAN line of a booking with a length-limited, linear `extractIban`. Trade Republic and the
  generic parser return `null`.
- **Detection** (`server/transferDetection.ts`): the pure `detectTransfers()` applies the IBAN
  strategy first, then the match strategy (same amount to the cent, ±3 days, exactly one
  candidate), then the replaced-income lookup and the claim check across rows.
- **API** (`server/routes/transfers.ts`): read-only `POST /api/transfers/detect`, Zod-validated
  (`detectTransfersRequestSchema` in `shared/schema.ts`), candidates loaded with the new
  `storage.getTransactionsBetweenDates()`.
- **Client**: `client/src/lib/transferDetection.ts` (detection hook, row updates, payload fields,
  deletion of replaced incomes) and `client/src/components/TransferCell.tsx`, used by both
  `ImportPDF.tsx` and `ImportPaperless.tsx`.

No schema change and no new dependency.

### Notes

- Deleting a replaced income happens client-side, after the batch save (ARCH-017 Key Decisions).
  The two requests are not atomic. The failure mode is the same double count as before this
  feature, and it is reported to the user (AC-017-17, TC-017-17).
- ARCH-017 Open Question 2 is still open: where ING and Trade Republic statements show the
  counterparty IBAN has to be checked against real statements. Until then those parsers rely on
  the match strategy only.
