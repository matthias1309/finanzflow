## Summary

On macOS about one full `npm test` run in 5–7 failed with a random wrong status (401 in
`pdf.test.ts`, 404 for an existing id in `transactions.test.ts`, non-array body in
`categoryRules.test.ts`). Root cause (CR-005 finding 3a): `request(app)` makes supertest start a
new server per request on an ephemeral port bound to `::` and connect to `127.0.0.1`; a parallel
Vitest process can bind the same port on `127.0.0.1`, so the request reached another test file's
app.

Change: new `tests/server/loopbackServer.ts` with `listenOnLoopback(app)`, which binds one server
per test file to `127.0.0.1` and waits for `listening` (supertest only reuses a server that
already has an address — otherwise it calls `listen(0)` on `::` again). All 11 API test files use
it and close the server in `afterAll`. `testing-practices.md` documents the pattern.
