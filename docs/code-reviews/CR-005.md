## Summary

Acceptance review of the whole template migration (`docs/MIGRATION-PLAN.md`, Sessions 0–10,
PRs #5–#17). The migration plan called this "CR-001"; that number was already taken by the
Session 5 retrofit review, and CR-002 … CR-004 followed for Sessions 6, 7 and 9, so this review
takes the next free number.

Scope: the migration's goal — "V-Model template with full traceability, a green quality baseline,
and the standard `.claude/` setup, without changing application behavior" — checked against the
repository state on `main` after PR #17, plus the Session 11 acceptance runs (`/traceability`,
`/test-coverage`, `/system-map`).

This review approves the **migration**. It does not approve the application's open
implementation bugs — they were found by the migration, are pinned by `known issue:` regression
tests, and are listed below as follow-ups with their own REQ/ARCH references.

| 3a | major (test infra) | `tests/server/api/*.test.ts` | **Flaky suite on macOS:** roughly one full `npm test` run in 5–7 fails with a random wrong status (401 in `pdf.test.ts`, 404 on an existing id in `transactions.test.ts`, non-array body in `categoryRules.test.ts`). Each file runs in its own process with a clean env (verified), so the response comes from *another* test file's app: `request(app)` starts a server on an ephemeral port per request, and on macOS a second process can bind the same port on `127.0.0.1` while the first listens on `::` — supertest's `127.0.0.1` request then reaches the wrong process (reproduced with two plain Node processes). Not caused by this PR (comment-only changes in those files). **Follow-up:** one server per test file bound to `127.0.0.1` explicitly. Linux CI has not shown it so far. |
| 4 | **blocker (app, not migration)** | `server/auth.ts`, `server/env-init.ts`, `server/env-defaults.ts` | Production start without `APP_PASSWORD_HASH` does not fail; it falls back to publicly known secrets (AC-001-08, TC-001-08). Needs a hotfix REQ-001 change. |
| 5 | **major (app)** | `server/routes/users.ts` | Session invalidation on user delete / password reset / TOTP reset is unimplemented (AC-015-07/09/13). |
| 6 | **major (app)** | `server/routes/users.ts` | `PATCH /api/users/:id/password` has no ownership check — any user can change any other user's password. No AC covers it yet. |
| 7 | major (app) | `shared/schema.ts`, `server/routes/transactions.ts` | Negative `amount` accepted (AC-004-09), transfer without target accepted (AC-004-06), month not validated on create (AC-004-10). |
