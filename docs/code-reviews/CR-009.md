## Summary

Adds a dedicated `parseTradeRepublic` bank parser so Trade Republic "Kontoauszug" cash-account
PDF statements are recognized and their transactions extracted automatically, instead of falling
through to "no transactions detected" as reported by the user. Reproduced with a real (redacted)
Trade Republic statement; the bug was that no parser recognized the bank at all — `detectBank`
returned `"Sonstige"`, and the generic fallback's `DD.MM.YYYY` date pattern doesn't match Trade
Republic's `DD Mon. YYYY` abbreviated-month date format, so zero transactions ever matched.

Scope: `server/pdfParser.ts` (`detectBank`, new `parseTradeRepublic`/`parseTradeRepublicDate`,
wiring in `parsePDF`), `tests/server/unit/pdfParser.test.ts` (9 new test cases), REQ-005 /
ARCH-005 / TEST-005 / ARC42 updated, `CHANGELOG.md`.

## Findings

None outstanding. One implementation issue was found and fixed during development, not left
open: the initial regex also matched the statement's money-market-fund purchase table (`Kauf`
rows with a bare `STK` number, no text description), producing bogus 1€ "expense" rows. Fixed by
requiring the description capture group to contain at least one letter; regression test added
(`ignores GELDMARKTFONDS purchase rows...`).
