## Summary

Closes CR-011 finding #4: 12 Playwright tests in `tests/e2e/{accounts,categories,login,users}.spec.ts`
failed on `main`. Investigating each failure found one production bug and several stale specs.

- **Production bug (`server/createApp.ts`):** `authRateLimiter` was mounted globally in addition
  to `POST /api/auth/login`. Every failed request (unauthenticated `401`s, `404`s) counted as a
  failed login, failed logins counted twice, and once the limit was hit, every request, including
  the SPA shell, answered `429` for 15 minutes. In the E2E run the earlier specs used up the
  limit, so all later login/users specs got the 429 page. The limiter now guards only the login
  route, as ARCH-001 specifies. New test `tests/server/api/auth-rate-limit.test.ts` (TC-001-05)
  closes a gap that had been left open since Session 10.
- **Specs:** hash routes (`/#/login`, `/#/users`, `/#/accounts`, `/#/categories`) instead of path
  routes; `toHaveURL` instead of `waitForURL` (a hash change fires no `load` event); TOTP specs
  create their own 2FA-enrolled user via the API (`createUserWithTotp`); the logout spec logs in
  and clicks "Abmelden"; account edit/delete target the test's own card instead of `.first()`.
- **UI:** the login card title gets `role="heading"` / `aria-level={1}`, because the page had no
  heading at all.
