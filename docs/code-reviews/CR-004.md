## Findings

_Pre-existing behavior in already-shipped code (not introduced by this PR), surfaced while writing
ARCH-010 against REQ-010's ACs. Not a regression from Session 9's own changes — Session 9 changed
no application code._

| # | Severity | File / Line | Description |
|---|----------|-------------|-------------|
| 1 | **medium** | `server/routes/summary.ts:33` (`GET /:month`) | The route reads `req.params.month` and uses it directly with no format validation, unlike the sibling `GET /api/transactions?month=` (`server/routes/transactions.ts`), which validates via `monthSchema`. **Confirmed by direct test**: `GET /api/summary/2026-4` returns `200` with `{"totalIncome":0,"totalExpenses":0,"accountSummaries":{},...}` rather than the `400` AC-010-06 requires. Lower severity than the Session 6/7 findings because it fails safe — no data corruption, just a silently-empty result instead of a clear client error — but it means a client-side bug constructing a malformed month string would be invisible rather than surfaced. |
