## Summary

GitGuardian flagged a "Generic High Entropy Secret" in `matthias1309/finanzflow`, pushed
2026-09-24. Investigation found that the Session 0 fix (PR #5) only removed the tracked
`secrets.env` file — the same secret values remained hardcoded as source-code fallbacks in three
places: `server/auth.ts`, `server/env-init.ts`, and `server/env-defaults.ts`. This was already a
known 🔴 follow-up in `docs/MIGRATION-PLAN.md` and `docs/architecture/ARCH-001.md`, sharpened by a
Session 10 finding that the production fail-fast check (AC-001-08) never actually fired.

Changes:
- Deleted `server/env-init.ts` — confirmed dead code (not imported by any runtime module, only
  referenced in `vitest.config.ts`'s coverage exclude list, which was updated accordingly).
- `server/env-defaults.ts` now gates the `APP_PASSWORD_HASH` / `SESSION_SECRET` /
  `TOTP_ENCRYPTION_KEY` fallbacks to `NODE_ENV === "development"` only, and generates
  `SESSION_SECRET` / `TOTP_ENCRYPTION_KEY` with `crypto.randomBytes` at process start instead of
  fixed literals (`APP_PASSWORD_HASH` stays a fixed, documented dev-only bcrypt hash — not high
  entropy, needed for a reproducible local login).
- `server/auth.ts` no longer sets any fallback value itself; it only validates. The production
  fail-fast check now applies unconditionally to `NODE_ENV === "production"` — the previous
  `DOCKER_DEPLOY !== "true"` exception is removed, since AC-001-08 never specified one and it was
  the actual root cause (a Docker-based production deploy with a missing env var silently used the
  known fallback instead of exiting).
- `docs/architecture/ARCH-001.md`, `docs/architecture/ARCH-015.md`, and
  `docs/MIGRATION-PLAN.md` updated to reflect the fix and close out the 🔴 follow-up.
